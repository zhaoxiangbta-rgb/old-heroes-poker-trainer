# Solver V4 development adapter

This folder is development-only. The shipped poker trainer loads the generated
strategy pack and never invokes Python, Rust, Node, a network service, or an AI
model.

Reference solver:

- project: `amaster97/poker_solver`
- source commit: `f78f1b2bc338dd8cbb5226ecb8398bbdb3635676`
- release: `1.11.0`
- license: MIT
- algorithm: tabular Discounted CFR (DCFR), with the solver's vector
  range-vs-range Rust path preferred for production data

The adapter accepts the solver CLI `--walk-tree --format json` output. It keeps
only on-path hero nodes, normalizes action names and pot fractions, classifies
the board family, preserves the opponent hand-class range, and writes the
deterministic V4 pack plus a SHA-256 manifest. Runtime lookup includes actual
heads-up action order and weighted opponent-range overlap; an unrelated range
cannot borrow a frequency merely because the visible board happens to match.

```bash
node tools/solver-v4/import-solve.mjs \
  --output public/assets/strategy-v4/strategy-v4-reference.json \
  /tmp/solve-a.json /tmp/solve-b.json
```

Golden hand examples are tests only. The importer and runtime never read a
golden-case identifier and do not contain hand-specific advice branches.

`reference-spots.json` is the reproducible generation recipe for the bundled
reference pack. These spots are texture/strength coverage anchors, not runtime
rules. A production pack is generated by checking out the pinned Solver commit,
running each recipe with `subgame --walk-tree --format json`, then importing all
raw outputs. The manifest stores a SHA-256 over the raw Solver inputs, so a pack
cannot silently claim a different source corpus.

The current reference corpus is deliberately honest: it provides exact river
subgame nodes. Flop/turn and multiway states remain on the local combination
range resolver unless a verified Solver node exists; the UI identifies which
path answered the decision. No approximate node is labelled as an exact Solver
answer.
