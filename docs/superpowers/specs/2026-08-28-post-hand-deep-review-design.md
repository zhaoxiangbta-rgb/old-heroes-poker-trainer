# 整手结束后深度精算复盘设计

**日期：** 2026-08-28
**状态：** 已确认，待实施计划
**适用项目：** `poker-decision-trainer`

## 1. 目标

牌局进行中继续使用有严格时间预算的快速策略计算，保证点击动作后立即响应。整手结束后不展示基础复盘，而是进入独立的“正在精算”流程；精算完成后一次性展示可用于初中级训练的完整复盘。

深度复盘必须：

- 完全离线，不依赖网络、Codex、Python、Node 或外接 AI。
- 不改变已结束牌局的发牌、行动、结算和输赢结果。
- 以规则引擎提供的合法动作、底池、主池/边池和有效筹码为唯一事实源。
- 按决策时可见信息重建范围，禁止使用当时不可见的对手底牌。
- 固定种子、策略版本和计算配置可重复得到相同结果。
- 支持取消、失败恢复、历史牌局重新精算和本地持久化。

## 2. 用户流程

### 2.1 正常完成

1. 牌局结算动画结束。
2. 页面进入“正在精算”，不先展示低精度复盘。
3. 页面依次显示当前阶段：
   - 整理完整行动线
   - 重建逐街范围
   - 计算候选动作权益与 EV
   - 生成教学点评
   - 保存复盘结果
4. 精算完成后一次性进入完整复盘。

进度按已完成任务数计算，不伪造精确剩余时间。界面保持可响应，并提供“取消精算”。

### 2.2 取消

点击“取消精算”后立即终止后台任务，返回该手结算页，并显示：

- `重新精算`
- `开始下一手`

取消不删除牌局和行动记录，不生成能力评分，也不把未完成结果写入弱点报告。历史牌局中显示“复盘未完成”，可随时重新精算。

### 2.3 失败或程序关闭

- 计算异常时显示可读错误，并提供“重新精算”和“开始下一手”。
- 程序关闭时不保存半成品；下次打开该手时显示“复盘未完成”。
- 已完成且计算配置未变化的复盘直接读取本地结果，不重复计算。
- 策略版本、算法版本或计算配置变化后，旧结果仍可查看，同时提供“使用当前版本重新精算”。

## 3. 计算架构

### 3.1 双层职责

牌局中和牌局后使用同一规则事实、范围模型和策略协议，但预算不同：

- `实时层`：固定小预算范围抽象，用于牌桌提示和对手行动，必须优先响应速度。
- `深度层`：整手结束后在后台重新计算所有英雄决策点，用于最终评分和详细复盘。

实时层的临时 EV 不直接成为最终能力评分。最终评分只读取成功完成的深度结果。

### 3.2 后台执行与取消

深度计算运行在独立 Worker 中，主线程只接收：

```ts
type DeepReviewEvent =
  | { type: "progress"; stage: DeepReviewStage; completed: number; total: number }
  | { type: "completed"; review: DeepHandReview }
  | { type: "failed"; code: string; message: string }
  | { type: "cancelled" };
```

每个权益计算批次都检查取消信号，避免按钮只能改变文字而无法真正停止运算。任何 Worker 结果写回前都校验牌局 ID、种子、状态哈希和请求 ID，防止旧任务污染新牌局。

### 3.3 精度策略

- 单挑翻后：枚举所有合法加权对手组合；在剩余公共牌规模可控时枚举全部 runout。
- 单挑组合量过大时：按固定顺序分块计算，保留累计误差界和实际覆盖率。
- 多人底池：完整组合枚举可能发生组合爆炸，因此使用去除冲突牌后的联合范围采样、分层抽样和固定种子高预算模拟。
- 河牌：没有未来公共牌，遍历全部合法加权范围组合。
- 翻前：使用版本化翻前蓝图与组合范围，不声称是完整六人无限注求解。

结果必须记录 `exact`、`enumerated` 或 `sampled`，并展示样本数、覆盖率、置信度和算法版本。只有真正完整枚举的节点可以标记“精确枚举”。

## 4. 深度复盘数据

每手保存一个版本化结果：

```ts
type DeepHandReview = {
  version: 1;
  status: "completed";
  handNo: number;
  seed: number;
  stateHash: string;
  strategyVersion: string;
  calculatorVersion: string;
  completedAt: string;
  summary: HandReviewSummary;
  decisions: DeepDecisionReview[];
};
```

每个英雄决策点至少包含：

- 街道、位置、人数、身后玩家、SPR、主池/边池和有效筹码。
- 动作前完整行动线与当时的合法动作边界。
- 每位对手在该决策点的范围摘要，以及相对上一节点的增减变化。
- 手牌对联合范围的权益、底池赔率、干净补牌、脏补牌和反向隐含赔率。
- 弃牌、过牌、跟注和多个合法下注尺寸的 EV、频率、风险与计算精度。
- 用户实际动作、推荐动作、可接受混合、标准化 EV 损失和严重程度。
- 价值、保护、半诈唬、纯诈唬、控池或诱导等行动意图。
- 命中的弱点标签、思路正确处、需要纠正处和一条可执行核心规则。

整手摘要从各决策点提炼，不根据本手输赢改变评价。

## 5. 复盘界面

完整复盘一次性呈现：

1. **整手结论**：总体评分、最大 EV 损失点、做得最好的一点、最需纠正的一点。
2. **行动时间线**：逐街展示真实行动、底池变化、下注尺度和英雄决策。
3. **决策卡片**：实际动作与推荐混合、候选 EV、风险和精度标识。
4. **范围变化**：展示组合类别的进入、退出和权重变化，不泄露未摊牌底牌。
5. **赔率与补牌**：权益、所需胜率、干净/污染补牌、身后风险和多人影响。
6. **核心规则**：用中文解释为何该动作是价值、保护、诈唬、控池或诱导。

复盘中的数值事实来自本地计算结果。可选解释模型只能润色这些事实和回答追问；模型失败时完整复盘仍可离线使用。

## 6. 状态与持久化

牌局增加独立的复盘任务状态：

```ts
type DeepReviewStatus =
  | "not-started"
  | "calculating"
  | "completed"
  | "cancelled"
  | "failed";
```

SQLite、IndexedDB 和 JSON 导入导出保存：

- 状态哈希、策略版本、计算器版本和配置版本。
- 已完成的 `DeepHandReview`。
- 取消或失败状态及非敏感错误码。

不持久化 Worker 临时缓冲、未完成累计值、API Key、隐藏底牌推断或日志中的密钥。公开导出仍不含任何密钥。

弱点报告、渐进课程和总评分只统计 `completed` 且非安全降级的深度决策结果。取消、失败和旧版快速估算不计分。

## 7. 性能与资源边界

- 精算运行时主线程帧率和按钮响应不受计算阻塞。
- 默认桌面单手目标在数秒到数十秒内完成；复杂多人池显示真实进度，不承诺虚假固定时长。
- 移动端使用更低但仍明显高于实时层的预算，并在系统资源不足时减少批次，而不是导致页面崩溃。
- 每个任务设硬性内存上限和最大组合预算；达到上限时返回带置信度的 `sampled` 结果，不伪装成精确值。
- 已完成结果缓存后，再次打开应在 200 ms 内进入复盘内容。

## 8. 验证要求

### 8.1 正确性

- 所有候选动作和尺寸均在保存的规则引擎合法边界内。
- 单挑小牌面与独立完整枚举交叉核对。
- 河牌范围遍历结果与手工构造样本一致。
- 多人范围消除已知牌和玩家间组合冲突。
- 主池、边池、平分、全下和不同有效筹码 EV 守恒。
- 未摊牌对手底牌不进入当时范围、评分或解释。
- 同一牌局、版本和配置重复精算结果一致。

### 8.2 生命周期

- 完成后只保存一份幂等结果。
- 取消能真正停止 Worker，且不保存半成品、不计分。
- 关闭后重新打开可识别未完成任务并重新精算。
- 旧任务结果不能覆盖新牌局或新版重算结果。
- 失败时牌局仍可开始下一手。

### 8.3 回归

- 牌局中的点击响应和实时策略性能不得退化。
- 现有牌型、结算、筹码、合法下注、种子重放和离线降级测试继续通过。
- Mac、Windows、离线移动版均能运行精算、取消、保存和重新打开。

## 9. 分阶段实施

1. 定义深度复盘数据、状态哈希、持久化兼容和决策快照。
2. 建立 Worker 协议、进度、取消、失败恢复和 UI 状态机。
3. 实现单挑高精度计算及交叉核对。
4. 实现多人联合范围高预算计算、边池 EV 和置信度。
5. 接入最终评分、弱点报告和完整复盘界面。
6. 完成桌面、移动、导入导出、性能和打包验证。

每一阶段都必须保持牌局可玩；不得用未完成的精算结果替换当前稳定评分。
