# 对称操作台与立体底池筹码设计

## 目标

在不增加底部操作台高度、不改变下注规则和金额映射的前提下，完成三项视觉修正：

1. 上方非等比下注横杆严格居中。
2. 下方左侧尺度键和右侧行动键分别在等宽区域内居中，中间手牌保持桌面几何中心。
3. 底池筹码从横向平铺改为多列纵向叠高，让底池量感随金额增长。

## 上方横杆

- 使用对称三列：`左侧精确金额区 | 中间横杆 | 右侧平衡留白区`。
- 左右两列始终等宽，因此中间横杆不受金额输入框影响，其几何中心与操作台、手牌中心一致。
- 横杆仍保留非等比金额映射：最低到底池占左半，底池位在中心，底池到 `ALL IN` 占右半。
- `最低 / 半池 / 2/3池 / 底池 / ALL IN` 标记位置不改变，仅修正整个轨道的居中关系。
- 1440×900 和 1100×760 两个桌面断点下，横杆中心相对手牌中心偏差不超过 2px。

## 下方三区

- 使用对称网格：`minmax(0, 1fr) | 138px | minmax(0, 1fr)`。
- 左侧区包含三个尺度铭牌及余码/位置；右侧区包含弃牌、过牌和跟注/下注。
- 左右区域等宽，内容各自设有相同的最大宽度并水平居中；不再使用 33% 和 35% 的非对称定位。
- 中间手牌宽高与字号不变，不为了居中而缩小。
- 左右按钮高度、真实素材、禁用态和按下反馈全部保留。
- 在紧凑桌面宽度下，优先缩小三区之间的间距，不破坏左右等宽和中线。

## 立体底池筹码

- 采用“真实牌局筹码堆”方案：3–6 列，每列 1–6 枚筹码纵向叠放。
- 底池金额按稳定阶梯映射为视觉量，不按“一筹码等于一单位”渲染：
  - 小底池：3 列，最高 2 枚。
  - 中底池：4 列，最高 3–4 枚。
  - 大底池：5 列，最高 5 枚。
  - 超大底池：6 列，最高 6 枚。
- 同一列内的筹码使用小幅纵向偏移形成叠高，相邻列略微高低错落和旋转，但不做散乱筹码山。
- 每列使用已有真实筹码图像，不用 CSS 图形或占位符代替。
- 底池文字仍只在筹码堆上方显示一次。
- 筹码堆的宽度不超过 220px，高度不超过 82px，与公共牌和玩家下注区保持至少 8px 间隔。
- 落池动画结束时，新筹码从堆顶短距离落下，整堆仅轻微回弹；不改变规则引擎的底池更新时机。

## 实现边界

- 不改动 `mobileBetChoices`、`mobileBetRailNodes`、`mobileBetPresetTarget` 或任何合法金额计算。
- 不改动底池、边池、筹码总账和赢家结算逻辑。
- 不改动移动端操作区；立体底池筹码组件如被共用，移动端必须保持现有布局或单独限制。
- 不增加网络、第三方图库或新的运行时依赖。

## 验收与测试

- 单元测试覆盖四个底池阶梯的列数、最大叠高和筹码图片路径。
- 桌面视觉测试覆盖：横杆中心偏差≤2px，左右区域宽度差≤2px，左右内容分别居中，手牌中心偏差≤2px。
- 筹码堆在宽屏和紧凑屏下不与公共牌、底池文字、玩家下注区重叠。
- 保留现有飞筹码、弃牌、减少动画、声音和二次确认行为。
- 通过全量单元测试、代码检查、生产构建以及 1440×900 / 1100×760 桌面截图对照。
