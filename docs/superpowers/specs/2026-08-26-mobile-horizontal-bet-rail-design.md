# 移动端横向下注推杆设计

## 目标

将移动端下注推杆由纵向改为横向，降低操作区高度并扩大牌桌可视面积，同时保留合法金额连续选择、预设下注尺寸、防重复提交和 ALL IN 反馈。

## 已确认布局

采用“紧凑双翼布局”：

- 操作区最上方为横向推杆，占可用宽度但不进入牌桌。
- 推杆整合五个吸附节点：`最低`、`½`、`⅔`、`1×`、`ALL IN`。其中 `½`、`⅔`、`1×` 分别代表半池、2/3 池和底池，不再显示独立预设按钮。
- 横杆仍允许选择节点之间的任意合法金额；拖动经过节点时产生磁吸反馈，松手落在吸附阈值内时对齐到该节点。
- 达到最右端时显示金色 `ALL IN`。
- 当前选中金额显示在推杆上方中央，不遮挡滑块。
- 操作区下方中央显示玩家两张手牌；牌面继续使用当前的大点数、大花色设计，并保持为操作区最强视觉中心。
- 左翼为非交互的玩家筹码信息区：写实筹码堆、`余码 N` 和 `你 · 位置`，用于平衡右侧行动按钮的视觉重量。
- 右翼显示行动按钮：弃牌、过牌、跟注/加注。只显示规则引擎当前允许的操作。
- 跟注与加注继续复用同一个主按钮：最低位置是跟注或最小下注，推动后自动切换为下注/加注，最右端切换为 ALL IN。

## 尺寸与适配

- iPhone 14 Pro Max 竖屏操作区目标高度为 142px，允许范围 138–150px；现有约 202px 的操作区至少减少 50px。
- 横向轨道有效宽度不小于 220px，滑块触摸区高度不小于 44px。
- 左右两翼按钮触摸区均不小于 44×44px。
- 中央手牌单张牌宽不小于 52px，点数和花色尺寸不得缩小。
- 430×760 紧凑竖屏仍保持相同结构；必要时缩小翼间距，不缩小触摸区。
- 932×430 横屏取消原来的纵向推杆特例，仍使用横向轨道；操作区位于牌桌右侧时按区域宽度自适应。

## 组件与数据流

- 将 `VerticalBetSlider` 重命名为 `HorizontalBetSlider`，接口仍接收 `choices`、`value`、`disabled` 和 `onChange`。
- 原生 `range` 改为水平语义，`aria-orientation="horizontal"`。
- 合法下注金额仍完全来自 `mobileBetChoices(game)`；滑块仅在合法金额索引间移动，不自行计算金额。
- 五个吸附节点由最低合法金额、`mobileBetPresetTarget` 的三个池比目标和最大合法金额合并去重，再映射到 `mobileBetChoices(game)` 中最近的合法值。
- 吸附仅改变选择值，不直接提交行动；用户仍需点击右侧主按钮确认。
- `MobileFloatingControls` 只调整 DOM 分区和样式，不修改 `send()` 锁定、防连点和异常恢复逻辑。

## 视觉设计

- 横杆使用黑色皮革槽、黄铜刻度与圆形金属滑块，延续当前写实俱乐部风格。
- 最低金额放在轨道左端下方，`ALL IN` 放在右端下方；仅到达最大值时增强金色高光，不持续闪烁。
- 横杆节点采用小型黄铜雕刻标记，不做成独立矩形按钮；当前吸附节点显示克制的暖金光环。
- 左侧筹码堆使用本地筹码视觉资产或 CSS 复用现有筹码材质；右侧行动继续使用实体筹码按钮材质。
- 操作区背景继续使用本地皮革纹理，所有视觉资源保持离线。

## 测试与验收

- 单元测试验证水平语义、五节点目标映射、节点去重、吸附阈值、任意合法金额选择、最大值 ALL IN 状态和锁定状态。
- 交互测试验证预设按钮不直接提交、主按钮随滑块从跟注切换为加注、重复点击仍只提交一次。
- Playwright 在 430×932、430×760、932×430 验证：操作区高度不超过 150px、轨道水平、所有按钮触摸区至少 44px、手牌完整可见、操作区不覆盖牌桌、无横向溢出。
- PWA 构建与离线缓存行为不变。

## 不在本次范围

- 不改变规则引擎、下注合法性或下注尺寸算法。
- 不改变桌面端操作栏。
- 不新增五节点以外的快捷下注档位，也不改变筹码飞行动画。
