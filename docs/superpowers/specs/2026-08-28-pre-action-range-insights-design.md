# 下注前牌力、坚果路径与对手范围分析设计

日期：2026-08-28

状态：待用户审核

适用项目：老英雄牌局桌面端与移动端

## 目标

在每个英雄决策点补充可审计的下注前分析，使用户在行动前能够快速回答三个问题：

1. 当前手牌可能通过哪些路径改善，下一张和到河牌分别有多大概率？
2. 当前牌面上成为绝对坚果或近似坚果的概率是多少，哪些补牌是脏补牌？
3. 每位对手根据位置、行动线、下注尺寸、画像和牌局风格，可能持有什么范围；面对英雄的不同行动会怎样响应？

规则引擎仍是唯一事实源。功能只使用当前可见牌与公开行动，不读取未摊牌底牌，不预测或泄露已经生成但尚未发出的未来牌。

## 已确认范围

采用“两层信息结构”：

- 默认简报控制在一屏内，供用户在数秒内阅读。
- 展开详情显示逐个对手的组合分类、范围变化原因和尺寸反应矩阵。
- 桌面端只修改右侧可调教学栏。
- 手机端只增加一条摘要和可上拉的半屏详情层。
- 桌面与手机现有牌桌、头像、筹码、公共牌、手牌、横向下注杆、下注尺度按钮、弃牌、过牌、跟注和确认操作均不得修改布局、样式、尺寸、事件或交互节奏。

不在本期范围：求解器级别的完整博弈树训练、联网获取策略、读取真实对手底牌、修改现有下注控制区、以模型解释覆盖本地计算结果。

## 信息结构

### 默认简报

每个英雄决策点显示：

- 当前牌力与主要成牌路线。
- 下一张牌命中主要牌型的概率。
- 到河牌前累计命中主要牌型的概率。
- 到河牌成为绝对坚果和近似坚果的概率。
- 干净补牌数、脏补牌数和最重要的反超风险。
- 当前最相关对手的范围摘要：强价值、一般成牌、听牌、诈唬或空气。
- 对手面对英雄跟注、半池、2/3 池、底池及全下时的弃牌、跟注、再加注概率摘要。
- 计算精度和置信度标签。

### 展开详情

逐个仍在牌局中的对手显示：

- 当前加权组合数。
- 两对及以上、顶对或超对、中弱对子、强听牌、弱听牌、诈唬或空气的权重。
- 位置、翻前行动、每街下注尺寸、入池人数、玩家画像和牌局风格分别造成的范围变化。
- 英雄各合法候选动作下，对手弃牌、跟注、再加注的概率。
- 对手继续范围会收窄到哪些牌力或听牌类别。
- 范围估计置信度及导致低置信度的原因。

### 翻前专用信息

翻前不显示“坚果概率”。替换为：

- 起手牌等级和位置基准范围。
- 当前行动线下的入池、加注、跟注与弃牌倾向。
- 有效筹码、身后玩家及被挤压风险。
- 面对不同尺寸时，对手范围和响应概率。

## 概率定义

### 牌型概率

“下一张”按剩余合法牌逐张精确枚举。“到河牌”按剩余合法转牌与河牌组合精确枚举。牌型结果采用互斥的最终分类，同一运行牌不会同时计入多个最终牌型总数；界面可额外显示它经过了哪些改善路径，但不得把重叠路径直接相加。

### 绝对坚果

在某个未来公共牌面上，英雄最佳五张牌不可能被任何与已知牌不冲突的合法两张对手底牌击败。允许平分时必须标为“并列坚果”，不得计为独占坚果。

### 近似坚果

不是绝对坚果，但在当前所有对手无冲突的加权联合组合中，至少一位对手能击败英雄的概率不超过 5%。单挑时该定义退化为对手两张牌的加权组合占比。界面必须同时显示其阈值定义，避免把“很强”误写为“坚果”。

### 干净与脏补牌

干净补牌是在当前对手加权范围下显著提高英雄权益，且不会同时高频完成对手更强牌的牌。脏补牌是表面改善英雄牌型，但因公共牌配对、更高同花、更高顺子、葫芦或身后玩家范围而存在明显反超风险的牌。分类使用逐张牌面对所有仍在池中的对手联合范围计算，不以单个代表组合替代多人判断。

## 对手范围和响应模型

### 范围更新

为每位对手维护独立加权组合范围，并按以下信息逐街更新：

1. 位置与有效筹码建立初始范围。
2. 翻前开池、跟注、3-bet、4-bet、挤压及下注尺寸更新范围。
3. 翻后结合牌面纹理、行动顺序、下注尺寸和多人池状态更新范围。
4. 玩家画像和牌局风格只作为可配置偏移，不能绕过规则或制造不可能组合。
5. 已知牌阻断和其他对手已采样组合必须实时移除。

### 动作响应

针对英雄当前合法动作集合计算每位对手的响应分布：

- 过牌或跟注。
- 半池、2/3 池、底池等合法下注或加注尺寸。
- 全下。

每个动作下，对手的弃牌、跟注、再加注概率之和必须为 100%。若某类动作在当前规则状态不合法，其概率固定为零且不显示。输出同时包含响应后的继续范围摘要。

### 多人池

多人计算使用无冲突的联合范围抽样或可行时的精确枚举，不能把各对手独立胜率直接相乘。行动预测需计入身后玩家，英雄对首位对手的加注也必须评估后续玩家继续或再加注的风险。

## 计算架构

采用混合实时架构：

1. 主线程生成不可变的公开决策快照和任务标识。
2. 快速计算 Worker 执行剩余牌枚举、最终牌型、坚果、补牌及基础赔率计算。
3. 范围计算 Worker 使用固定种子、固定预算和逐个对手范围，计算范围摘要及动作响应。
4. UI 先接收快速事实，再无闪烁补充范围结果。
5. 每次新动作、换街、结束牌局或开始下一手都会取消旧任务；返回结果必须同时匹配牌局种子、手数、街道、日志索引及状态哈希。

下注控件不等待 Worker。分析未完成、失败或取消均不得锁定行动按钮。

## 精度、置信度与文案

每项结果标记以下来源之一：

- `精确枚举`：完整遍历剩余合法组合。
- `范围模拟`：固定种子和固定预算的加权联合抽样。
- `低置信度`：范围信息不足、有效组合过少、多人冲突率过高或预算超时。

默认使用中文解释。概率是基于可见信息的范围估计，不得使用“对手一定有”“必然弃牌”等确定性文案。

## 桌面与手机展示

### 桌面端

在现有右侧可调教学栏中替换简单的“赔率 / 补牌 / 风险”段落。默认简报显示三至五个关键事实卡和一个主要对手摘要；点击展开后显示逐个对手和响应矩阵。

左侧牌桌与下注区是锁定组件。实现代码不得修改其 DOM 结构、CSS、尺寸、位置、事件处理或动画。

### 手机端

牌桌与操作区保持现状。在二者之外增加一条紧凑摘要。用户点击或上拉时打开半屏详情层；详情层禁止点击穿透，向下滑或点击关闭后继续操作。详情层不得覆盖系统安全区中的主要操作按钮。

## 加载、失败和取消

- 新决策出现后立即清除旧结果，显示“牌型精算中”。
- 快速结果完成后先展示；范围结果未完成时显示独立加载状态。
- 范围计算失败时保留快速事实，并显示“范围估计暂不可用”。
- 用户行动后旧结果立即失效，不能短暂显示在下一街或下一手。
- Worker 异常、取消和超时只影响分析展示，不影响规则引擎和下注。
- 桌面端快速结果目标为 150 ms 内返回，范围模拟目标为 800 ms 内返回；iPhone 14 Pro Max 目标分别为 300 ms 和 1500 ms。超时后停止增加预算并保留已完成结果及置信度，不无限等待。

## 数据与重放

下注前分析使用公开决策快照，可保存以下结构化事实以支持准确重放：

- 计算器版本、范围模型版本、随机种子和预算。
- 状态哈希、街道、日志索引和合法动作集合。
- 牌型概率、坚果概率、补牌分类。
- 各对手范围摘要、响应分布和置信度。

不得保存未摊牌真实底牌、API Key 或任何由隐藏牌产生的派生信息。旧版牌局没有这些字段时按“未计算”展示，不伪造数据。

## 测试与验收

### 正确性

- 覆盖高牌、一对、两对、三条、顺子、同花、葫芦、四条和同花顺。
- 覆盖公共牌成牌、并列坚果、假坚果、公共牌配对反超和脏补牌。
- 将下一张和到河牌概率与独立暴力枚举交叉核对。
- 验证互斥牌型总概率、响应概率均在允许误差内合计为 100%。
- 验证阻断牌、范围冲突、多人联合范围和身后玩家风险。
- 验证不同位置、下注尺寸、行动线、玩家画像和牌局风格会产生预期方向的范围更新。
- 所有推荐候选及对手响应必须通过规则引擎合法性校验。

### 生命周期与性能

- 覆盖快速连续操作、换街、重新发牌、取消和 Worker 异常。
- 验证过期任务不会写入当前决策。
- 在桌面目标设备上验证快速事实 150 ms、范围模拟 800 ms 的性能目标；未达标时必须降级而非阻塞。
- 在 iPhone 14 Pro Max 上验证快速事实 300 ms、范围模拟 1500 ms 的性能目标，以及纵横屏、上拉层、安全区和触控。

### UI 回归

- 保存改动前后桌面端牌桌与下注区基准截图，验证锁定区域无视觉变化。
- 现有下注、过牌、弃牌、跟注、全下及横杆吸附测试必须原样通过。
- 手机端现有牌桌和操作区行为测试必须原样通过。
- 新增默认简报、展开详情、加载、低置信度、失败和取消状态测试。

## 完成标准

功能只有在以下条件全部满足后才算完成：

1. 桌面和手机每个英雄决策点均能看到默认简报并展开详情。
2. 牌型、坚果和补牌概率通过独立枚举交叉验证。
3. 逐个对手范围与动作响应可重放且不泄露隐藏牌。
4. 分析失败不会阻塞任何下注动作。
5. 现有牌桌和下注区的布局、样式及交互回归测试无变化。
6. 全量前端、Rust、PWA、桌面构建与真实浏览器验证通过。
