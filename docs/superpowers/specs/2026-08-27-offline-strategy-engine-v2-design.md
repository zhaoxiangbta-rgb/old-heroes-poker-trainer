# 离线德州扑克策略引擎 V2 设计

**日期：** 2026-08-27  
**状态：** 已确认，待实施计划  
**适用项目：** `poker-decision-trainer`

## 1. 目标

将现有以人工 EV 公式和固定概率为主的启发式策略，重构为完全离线的“抽象策略蓝图 + 本地局部解析”引擎，使六人现金局对手行为和训练评分达到初中级玩家可用水平。

引擎必须：

- 完全离线运行，对手决策不依赖网络、Codex 或外接大模型。
- 以本地规则引擎为唯一事实源，不按单手输赢评价用户。
- 对手决策、用户评分、推荐尺寸和整手复盘共用同一策略事实。
- 固定种子可精确重放决策和范围变化。
- 桌面策略数据不超过 500 MB，不在启动时全部载入内存。
- 明确称为“抽象均衡策略”，不声称已求解完整六人无限注 GTO。

## 2. 非目标

首版不做：

- 不在用户电脑上求解完整六人无限注博弈树。
- 不复制、嵌入或反向工程任何商业 Solver 的专有策略数据。
- 不用大模型生成合法动作、胜率、范围或 EV。
- 不为了包体积强行保存每个具体牌面和所有任意下注树。
- 不在首版把多人池结果标记为高精度单挑求解。

## 3. 总体架构

### 3.1 公开状态标准化器

输入只包含决策者合法可见的信息：

- 位置、盲注和有效筹码。
- 公共牌和已知手牌。
- 存活玩家、身后玩家和主池/边池。
- 完整行动线，包括每次真实移动筹码、动作前底池、动作后底池和加注到的街道总额。
- 当前合法动作和最小/最大加注到金额。

标准化器将实际牌局映射为稳定、版本化的 `PublicDecisionState`。策略模块不允许接收未摊牌对手的底牌。

### 3.2 逐玩家组合范围账本

每位对手分别维护 1326 种起手组合的权重。范围更新依据包括：

- 位置和有效筹码。
- 翻前行动、主动者和跟注者身份。
- 街道、公共牌结构和存活人数。
- 真实下注尺度、连续过牌、过牌加注和全下。
- 玩家画像对均衡基线的有界偏移。

范围账本必须支持快照，使历史牌局能按原策略版本重放。

### 3.3 离线策略蓝图

桌面安装包携带版本化的二进制策略分片：

```text
strategy/
  manifest.json
  preflop.bin
  flop-srp.bin
  flop-3bet.bin
  turn.bin
  river.bin
  multiway.bin
```

`manifest.json` 必须记录策略版本、生成算法版本、随机种子、迭代配置、筹码档位、节点数、分片哈希和最低应用版本。

应用按需读取分片，并使用有上限的 LRU 缓存。不得在启动时解压或载入全部策略数据。

### 3.4 节点匹配和插值

运行时按以下信息查找节点：

- 玩家数和位置。
- 翻前底池类型。
- 有效筹码和 SPR。
- 公共牌同构类和战略纹理类。
- 完整行动线和尺寸节点。

无完全命中时，只能在相邻筹码档位、尺寸节点和同类牌面之间插值。输出必须包含命中来源和置信度。

### 3.5 本地局部解析器

- 单挑底池：在蓝图基础上执行有限深度 CFR 修正。
- 多人底池：使用每位玩家的独立范围，计算范围对范围权益、实现率、身后继续风险、脏补牌和边池 EV。
- 超时时：立即返回当前最佳蓝图/插值结果，不阻塞牌桌操作。

### 3.6 画像偏移层和统一评分

标准均衡策略是唯一基线。普通朋友局、宽松疯狂局和个人画像只能对基线频率做有界、可说明的偏移。

机器人决策与用户评分共用以下输出协议：

```ts
type StrategyResult = {
  actions: Array<{
    action: "fold" | "check" | "call" | "bet" | "raise" | "all-in";
    toAmount?: number;
    potFraction?: number;
    frequency: number;
    ev: number;
    intent: "value" | "protection" | "semi-bluff" | "bluff" | "pot-control" | "induce";
  }>;
  confidence: number;
  source: "blueprint" | "interpolated" | "blueprint+resolver" | "multiway-resolver" | "safe-fallback";
  nodeId?: string;
  strategyVersion: string;
  rangeFacts: Record<string, number | string>;
  explanationFacts: Record<string, number | string>;
};
```

任何解释模型只能读取 `StrategyResult` 中的结构化事实。

## 4. 策略覆盖

### 4.1 翻前

默认盲注 1/2，覆盖六人桌以下有效筹码档位：

- 25BB
- 40BB
- 60BB
- 100BB
- 150BB
- 200BB

覆盖首入池、开放加注、跟注、3-bet、挤压、冷跟 3-bet、4-bet、短码全下、跟全下、盲注战和多人入池后的隔离加注。

### 4.2 单挑翻后

高精度部分覆盖：

- 单加注、3-bet 和 4-bet 底池。
- 翻牌、转牌和河牌连续行动线。
- 过牌、持续下注、延迟下注和过牌加注。
- 1/3池、半池、2/3池、满池、1.25倍池、1.5倍池和全下。

### 4.3 多人底池

多人池使用范围级解析，必须处理：

- 每位玩家独立范围。
- 真实多人组合权益和身后玩家继续概率。
- 坚果组合、脏补牌、共享补牌和反向隐含赔率。
- 主池、边池和不同有效筹码。
- 多人池价值阈值提高和诈唰频率下降。
- 连续过牌后最后位置依牌力和范围的合理偷池频率。

多人结果必须标记较低置信度，不得展示为精确 Solver 解。

## 5. 策略生成

### 5.1 生成流程

项目提供只在开发/发布阶段运行的生成器：

1. 构建标准翻前信息集和合法行动树。
2. 对抽象博弈执行 CFR/MCCFR 迭代。
3. 使用固定种子保存检查点、平均策略和收敛指标。
4. 对公共牌做花色同构归一化和战略纹理聚类。
5. 对常见单挑节点进行较高迭代精度求解。
6. 生成多人范围基准参数和固定校准样本。
7. 只导出达到质量门槛的二进制分片。

应用交付物只包含生成结果和运行时读取器，不依赖 Python、Node 或求解器运行环境。

### 5.2 牌面与手牌抽象

聚类不能只用最终牌型。特征至少包括：

- 当前组合权益及对目标范围的权益分布。
- 坚果潜力、阻断效果和反向隐含赔率。
- 干净/污染补牌和后续街道改善概率。
- 公共牌高度、连接度、同花度、成对情况和范围/坚果优势。

花色同构的战略等价牌面只保存一份。

### 5.3 任意下注尺度

蓝图保存常用尺度，但规则引擎继续允许任意合法整数金额。非标准尺度的处理规则是：

- 底池赔率和实际投入使用真实金额。
- 范围更新使用真实动作前底池和真实移动筹码。
- 策略频率在相邻尺寸节点之间插值。
- 超出有效插值区间的极端尺度进入局部解析。

## 6. 性能预算和降级

目标预算：

- 蓝图直接命中：20 ms 内。
- 插值节点：50 ms 内。
- 单挑局部解析：桌面端 150 ms 内。
- 多人范围解析：桌面端 250 ms 内。

超时必须返回当前最佳结果。动画中的“思考时间”与算法时间分离，用户提交动作后不得因解析器卡住界面。

策略包缺失、哈希损坏或版本不兼容时：

1. 明确显示“策略数据不可用”。
2. 使用只保证合法行动的安全降级策略继续牌局。
3. 该牌局不计入正式能力评分。
4. 密钥、隐藏底牌和策略缓存不写入导出文档。

## 7. 用户评分和复盘

评分使用 EV 损失，而不是“动作不同即错”：

```text
用户动作损失 = 当前节点最优混合策略 EV - 用户动作 EV
```

结果分为：

- 正确混合：策略支持且 EV 接近。
- 可接受偏移：频率较低，但 EV 损失很小。
- 明显失误：EV 损失达到可教学程度。
- 严重失误：在大额底池或深筹码下损失显著。

每手复盘展示策略版本、范围变化、节点来源、置信度、各动作频率/EV、推荐尺寸和行动意图。单手输赢不改变评分。

## 8. 持久化与兼容

新牌局记录至少增加：

- `strategyVersion`
- `strategySource`
- `strategyConfidence`
- `rangeSnapshotVersion`
- 候选动作频率和 EV
- 蓝图节点 ID
- 是否使用插值、局部解析或安全降级

旧牌局保持可重放，但显示：

> 旧版启发式策略，仅供牌局重放，不作为 V2 能力评分依据。

现有玩家名称、画像、牌局风格、筹码总账、随机种子和完整状态保持兼容。

## 9. 验证门槛

### 9.1 规则层

现有牌型、平分、边池、全下、行动顺序、最小加注、公共牌成牌和种子重放测试必须继续通过。

### 9.2 策略结构层

必须验证：

- 候选动作频率和为 1。
- 不生成非法动作。
- 范围不包含已知牌。
- 各玩家范围互相独立。
- 真实动作前底池和真实移动筹码能正确识别超池尺度。
- 强价值牌不会无条件弃牌，纯空气不会无条件继续。
- 连续过牌后合理牌类的下注频率不会降为 0。
- 相似节点中，多人池纯诈唰频率低于单挑底池。
- 河牌大加注范围整体强于小尺寸范围。

### 9.3 求解质量层

对可完整求解的抽象小博弈验证：

- 平均遗憾随迭代整体下降。
- 同一配置和种子的导出哈希一致。
- 近似可利用度低于发布配置所记录的门槛。
- 增加迭代后平均策略不出现无解释的大幅漂移。
- 蓝图直接命中、插值和局部解析的 EV 方向一致。

未达到门槛的分片不得进入正式安装包。

### 9.4 实战回归层

固定牌局集必须防止：

- 用户过牌后对手机械一路过牌。
- 用户超池下注后对手无条件弃牌。
- 用户加注后对手机械反加到全下。
- 多人池顶对按单挑强度处理。
- 强听牌面对超池不考虑赔率、范围和阻断牌。
- 强牌慢打、保护下注、抓诈唰和河牌薄价值无法区分。

每个样本保存完整公开状态、范围快照、策略版本、行动频率和 EV。

### 9.5 系统验证

- 现有 314 项测试必须继续通过。
- 至少模拟 10,000 手六人桌和 10,000 手单挑，不出现非法动作、死循环或筹码不守恒。
- 策略分片损坏必须触发明确降级。
- 未摊牌底牌不得进入对手策略输入、日志或复盘事实。
- Mac、Windows 和离线移动包分别执行产物完整性验证。

## 10. 分阶段交付

### 阶段一：策略内核基础

- `PublicDecisionState` 和隐藏信息隔离。
- 逐玩家组合范围账本。
- `StrategyResult` 统一输出协议。
- 现有超池尺度和多人连续过牌修复转为正式回归测试。

### 阶段二：翻前蓝图

- 六人桌筹码档位和常见翻前行动树。
- CFR/MCCFR 生成器、检查点和收敛报告。
- 二进制策略包导出和运行时读取。
- 机器人翻前决策和复盘评分统一接入。

### 阶段三：单挑翻后

- 牌面同构和战略纹理聚类。
- 单加注、3-bet 和 4-bet 底池蓝图。
- 非标准尺度插值和单挑局部解析。
- 延迟下注、过牌加注和超池防守回归集。

### 阶段四：多人底池

- 多玩家独立范围和多人权益。
- 身后风险、脏补牌、共享补牌和不同有效筹码。
- 主池/边池 EV 和多人置信度。
- 多人顶对、慢打、保护和身后玩家专项回归。

### 阶段五：训练与交付

- EV 损失评分和整手统一复盘。
- 历史牌局和策略版本迁移。
- 性能、内存和分片完整性验证。
- Mac、Windows、离线移动包构建和 GitHub 公开发布。

每个阶段必须交付可玩、可测、可回退的软件，不允许等全部完成后才首次集成运行。

## 11. 公开发布和授权

- 生成器、抽象配置、策略包格式和可发布数据必须可在公开 GitHub 仓库中合法分发。
- 任何新第三方依赖在引入前必须审核许可证和离线再分发条件。
- 本地玩家名称配置不进入公开策略包、日志或 Git 历史。
- 每个正式产物必须附带策略版本、包哈希、应用版本和完整性校验结果。
