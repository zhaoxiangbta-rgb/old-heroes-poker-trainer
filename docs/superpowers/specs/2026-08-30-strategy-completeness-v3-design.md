# 德州扑克策略完整性 V3 设计规格

## 背景与问题

当前翻前包虽然列出 169 类起手牌，但每个局面节点只保存“继续范围阈值”和“进攻范围阈值”，再通过单一手牌强度排序生成动作。这种表达无法稳定保留同花小 A、低对、同花连张和阻断型 3-bet 等非单调策略。

当前翻后策略将手牌压缩为少量牌力桶，主要使用单街即时 EV 比较过牌、跟注和几个尺度。它能处理基本位置、范围优势和对手响应，但不足以表达成对公共牌、范围压缩、英雄阻断更差跟注组合、后续街价值和不同尺度的弹性。因此会出现 A2s 在劫位无人加注时被机械弃牌，以及 A-A-x 上三条 A 被机械推荐满池等系统性偏差。

V3 不对单手牌添加特判，而是替换产生这些结论的策略表达和 EV 链路。

## 产品目标

- 为初中级玩家提供稳定、可解释、可复现的本地标准策略。
- 翻前不再由单一强度公式推导全部 169 类手牌的动作。
- 翻后决策同时考虑范围、牌面、阻断、对手继续范围、尺度弹性和后续街价值。
- 桌面版和移动版使用同一份源策略，只允许在压缩精度和实时计算预算上有差异。
- 不宣称等同商业 Solver 或完整六人无限注 GTO；所有近似结论保留版本、置信度和降级记录。

## 不可破坏的边界

1. 52 张牌、合法行动、筹码、边池、有效筹码、评牌和结算继续由规则引擎唯一决定。
2. 策略不读取未摊牌对手的暗牌，不按本手输赢评价动作。
3. 同一公开状态、范围快照、策略包版本和随机种子必须得到相同结果。
4. 桌面完整策略包上限为 500 MB；移动版必须可在 iPhone 14 Pro Max 上首次加载、安装和完全离线使用。
5. 桌面与移动不得人工维护两套不同的策略逻辑。
6. 未完成、校验失败或版本不匹配的策略包不得静默加载。

## 总体架构

```text
公开决策状态
  ↓
节点分类（位置/行动线/筹码/牌面族）
  ↓
源策略包查询 → 相邻节点插值
  ↓
当前范围与阻断重加权
  ↓
多街价值评估 → 合法动作与尺度混合
  ↓
有界玩家画像调整
  ↓
规则引擎最终合法性校验
```

源策略包是一级基线事实；实时计算只能根据当前范围、阻断、非标尺度和画像做有界修正，不能用简单启发式完全覆盖包内策略。

## 翻前完整动作矩阵

### 节点维度

- 六人桌位置：UTG、HJ、CO、BTN、SB、BB。
- 有效筹码：25、40、60、100、150、200 BB，中间筹码深度插值。
- 主要行动线：无人入池、面对溜入、面对开池、开池加平跟后挤压、面对 3-bet、4-bet 和全下。
- 动作线保留开池者位置、平跟人数、尺度类别、是否重新开放加注权和身后玩家数。

### 数据表达

每个节点对 169 类手牌直接保存归一化动作频率：

```ts
type PreflopHandStrategy = {
  hand: string;
  actions: Array<{
    kind: "fold" | "check" | "call" | "raise" | "all-in";
    sizeClass?: "open-2.0" | "open-2.5" | "open-3.0" | "three-bet-ip" |
      "three-bet-oop" | "four-bet" | "jam";
    frequency: number;
    ev?: number;
  }>;
};
```

手牌强度排序只用于质量检查和相邻节点平滑性对比，不再直接生成动作。同花小 A、阻断牌、小对和同花连张因此可在不同节点保留非单调混合。

### 来源与质量标识

策略包每个节点必须标记来源类型：已验证参考表、本地求解、相邻节点插值或安全专家基线。未取得可合法再分发的商业 Solver 数据时，不复制、不伪造其输出。

## 翻后牌面族与范围节点

### 牌面族

翻牌先按花色同构归一，再分类：

- 高牌级别：A/K 高、Q/J 高、中牌、低牌。
- 成对结构：未成对、顶牌成对、中低牌成对、三张公共牌同点数。
- 花色结构：彩虹、两同花、单色。
- 连接结构：离散、单卡顺缺口、高连接、四连顺风险。
- 动态变化：转河完成同花/顺子、公共牌再成对、超张、空白牌。

分类结果必须保存原始公开特征，避免不同范围含义的牌面被一个过粗的“dry/wet”标签覆盖。

### 手牌与范围特征

策略查询不只接收“坚果/强牌/中等牌”，而是接收：

- 当前五张或七张最佳牌型与踢脚档位。
- 口袋对成暗三条、公共牌成对后手牌成三条等不同组合结构。
- 手牌对对手更差跟注范围、更好继续范围和诈唬范围的阻断/反阻断。
- 当前摊牌价值、干净听牌、脏听牌、反向隐含赔率和被反超风险。
- 英雄范围与对手范围中上述组合的加权密度。

## 多街价值模型

每个候选动作的价值分成五部分：

1. **当街弃牌收益**：对手现在弃牌时获得的底池。
2. **更差牌继续价值**：对手以更差成牌或听牌跟注的组合权重与英雄条件权益。
3. **更好牌继续成本**：对手更好牌跟注或加注的概率、英雄的可继续性和额外投入。
4. **后续街价值**：转河牌分支上的二次价值、过牌诱导、控池、放弃和被反超成本。
5. **实现与方差惩罚**：无位置、多人池、高 SPR、脏听牌和不封顶范围下的权益折损。

实时决策不展开完整游戏树，而在源策略的相邻节点上对转河牌类别使用固定预算的确定性分支评估。牌局结束后的精算复盘可增加分支预算，但不改变当时已保存的策略版本和公开状态。

## 尺度弹性与价值捕获

对每个合法尺度，响应模型必须生成互斥的范围分段：

- 立即弃牌。
- 更差牌跟注。
- 听牌跟注。
- 更好牌跟注。
- 价值加注。
- 诈唬加注。

尺度变大时，每个组合的继续概率根据牌力、阻断、位置、街道和玩家画像变化，不得用同一个线性折扣应用于全范围。强牌的推荐尺度不由“英雄胜率”单独决定，而由各尺度实际保留的更差继续组合和后续街收益决定。

## 标准策略与画像调整

- 首先查询和评估标准策略。
- 牌局风格和具体玩家画像只修改对手范围权重、尺度弹性和候选动作频率。
- 画像偏移必须保留标准动作和原始 EV，并记录调整原因。
- 画像不得把明显负 EV 动作提升为主要教学结论，也不得产生无限反加。

## 桌面完整包与移动压缩包

### 单一源数据

仓库中保留一份规范化源策略定义和生成器。生成器输出：

- `desktop-strategy.pack`：保留更多筹码深度、尺度、牌面族和转河分支，总大小不超过 500 MB。
- `mobile-strategy.pack`：由同一源节点通过聚类、量化和稀疏化生成，保留主要动作、主要尺度与边界混合。

两个包必须有相同的源版本、节点语义和校验工具。移动包的主要动作与桌面包不一致时，构建必须在差异报告中列出该节点，超过容许门槛则失败。

### 加载和降级

- 包内保存 schema 版本、策略版本、生成算法版本、节点数、压缩参数和 SHA-256。
- 应用启动时校验 manifest 与主体哈希；校验失败时显示“策略包校验失败，已使用安全基线”。
- 安全基线只保证合法性和基本可玩，降低置信度且不计入正式能力评分。

## 策略完整性门禁

V3 不以少量固定牌例作为唯一验收。构建时生成并扫描策略空间：

### 翻前全矩阵检查

- 每个必需节点都有 169 类手牌，每手频率非负且合计为 100%。
- 所有输出动作和尺度符合节点规则。
- 位置变好时整体开池范围不异常收紧；压力层级提高时整体继续范围不异常扩张。
- 非单调类别允许有局部例外，但每个例外必须来自显式动作矩阵，而不是运行时特判。
- A2s 劫位无人加注等用户发现案例作为回归样本，但修复必须通过整个节点矩阵检查。

### 翻后属性与反例检查

- 牌面花色同构置换不改变策略。
- 候选动作金额合法，频率归一，EV 为有限数。
- 尺度变大时弱范围的继续率总体不增加，但真实强牌不能被机械归为弃牌。
- 价值下注必须有非零的更差继续范围；“更差继续价值”减少时，大尺度不得因英雄绝对牌力强而自动变成主要动作。
- 成对干燥牌面、单色牌面、高连接牌面、转河牌范围反转和多人池分别有批量反例。
- A-A-x 上弱踢脚三条等用户发现案例只作为属性门禁的一个样本。

### 交叉校验

- 翻前按位置和行动线汇总的范围频率必须输出可审计报告。
- 为一组固定公开状态保存独立参考结果区间，不强求逐频率完全相同，但主要动作、尺度档位和范围方向必须一致。
- 若未取得独立合法参考，该节点标记为“专家基线，未交叉校验”，不宣称求解精度。

## 性能预算

- 玩家轮到说话后，合法动作和基础操作区必须立即可用。
- 桌面标准策略查询与实时修正的 P95 目标为 150 ms，超时时使用包内基线并降低置信度。
- 移动标准策略查询与实时修正的 P95 目标为 250 ms。
- 牌局结束后精算允许使用更高预算，可取消，并在不改变当时策略版本的前提下补充更细的组合解释。

## 数据、重放与解释

每次决策保存：

- 策略包版本与包类型。
- 节点 ID、牌面族 ID、范围快照哈希和随机种子。
- 标准动作、标准频率、尺度和多街 EV 分量。
- 画像调整后的动作与偏移原因。
- 加载、插值、预算降级或安全回退状态。

教学文案优先说明“哪些更差牌会继续、哪些更好牌会继续、阻断如何改变价值”，而不是只显示牌力标签和一个总 EV。主要教学区不显示数据包内部编码、节点数和样本覆盖率；这些信息保留在可展开审计记录中。

## 兼容与迁移

- V3 使用新的策略 schema 和决策记录版本。
- 旧牌局使用当时保存的旧策略事实重放，不用 V3 覆写历史建议。
- 旧牌局可在用户主动点击“用新策略重新分析”时生成独立的 V3 复盘，原记录保留。
- 导入导出仍不包含 API Key，不序列化对手未摊牌的实际暗牌作为决策输入。

## 分阶段交付

### 阶段 1：完整翻前矩阵和完整性扫描

替换强度阈值算法，引入逐手牌动作矩阵、manifest、全矩阵检查和桌面/移动同源打包。翻前可单独发布和验收。

### 阶段 2：翻后节点语义与尺度弹性

替换过粗的牌力桶输入，建立牌面族、手牌组合结构、范围分段与对手尺度弹性。

### 阶段 3：多街价值与实时查询

引入固定预算后续街分支，将标准策略、多街 EV、画像调整和教学解释接入桌面与移动端。

### 阶段 4：全量验证、压缩和发布

完成属性扫描、独立参考交叉核对、桌面/移动差异报告、性能门、历史兼容、离线构建和安装包验证。

## 验收结果

V3 完成后，项目必须能证明：

- 建议来自显式策略节点和范围评估，不是对某张牌的硬编码。
- 翻前全节点矩阵完整、归一、合法且可审计。
- 翻后强牌尺度由更差继续范围和后续街价值支持，不是由绝对牌力直接决定。
- 桌面和移动使用同源策略，主要动作差异在构建时可见且受门禁限制。
- 用户发现的 A2s 和 A-A-x 三条案例通过，同类手牌和牌面的批量属性扫描同时通过。
- 玩家行动不被策略计算阻塞，降级状态可见，牌局可准确重放。
